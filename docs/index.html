The run loop, in one command

  1. Edit the variant

    Copy the skill, change the trigger words. v2-bad drops the commit verbs from its SKILL.md.

  2. Run both arms

    One command rolls out baseline and candidate on the same tasks, model and rollouts.

  3. Read the diff

    Each task gets a verdict and a category, with the runs and checks behind it.

The regression pipeline, wired once. Two arms, one config.

Four states an eval can hold

Pending, passed, failed or error. An error means the evaluator broke, never that the task failed, and a pending criterion never counts as a pass.

Rubric weights and scales are validated before the first rollout. Judge output records the judge model; human scores land per criterion.

Does it call real models?

Yes, through LiteLLM with your provider keys. The demo and tests run on a deterministic mock, and reports label mock output as simulated.

What does a run need?

Python 3.10 or later, a lab directory and task fixtures. Command tools run inside bwrap; without it they stay disabled rather than running open.

What counts as a regression?

A task that stops passing, a score drop, lost or false activation, or growth in tokens, latency or variance. Every threshold lives in lab.yaml.

Can I compare models too?

Yes. lab rerun --model runs the same experiment on another model, and the report groups every metric by model.

Where do run files live?

Plain files in the lab: run.yaml, eval.yaml, transcripts and regressions/<id>/. Nothing leaves the repository.

Change it, then measure it.

Free, open source, runs offline on mock. Three commands to a first verdict.
